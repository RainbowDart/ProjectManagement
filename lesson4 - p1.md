# Практическая работа №1. Декомпозиция программного проекта

## Задание 1. Создание WBS

1. Этап: Анализ и проектирование
   - 1.1. Сбор и анализ требований к системе
   - 1.2. Проектирование структуры базы данных (БД)
   - 1.3. Создание макетов пользовательского интерфейса (UI/UX)
2. Этап: Backend-разработка
   - 2.1. Реализация регистрации и авторизации пользователей
   - 2.2. Разработка API для создания и редактирования задач
   - 2.3. Разработка API для назначения исполнителей и смены статусов
   - 2.4. Реализация поиска и фильтрации задач
3. Этап: Frontend-разработка
   - 3.1. Верстка экранов входа и регистрации
   - 3.2. Верстка главного экрана (список задач)
   - 3.3. Создание форм для добавления и редактирования задач
   - 3.4. Внедрение поисковой строки и фильтров на клиенте
4. Этап: Тестирование и внедрение
   - 4.1. Функциональное тестирование API и интерфейса
   - 4.2. Исправление выявленных ошибок (баг-фиксинг)
   - 4.3. Развертывание системы на сервере
   - 4.4. Передача готового продукта заказчику

## Задание 2. Определение контрольных точек

1. Требования утверждены — готово ТЗ, утверждены макеты интерфейса и схема БД.
2. Ядро Backend готово — работают API для регистрации, авторизации и базовых операций с задачами.
3. Интеграция завершена — Frontend успешно связан с Backend, все основные сценарии работают в браузере.
4. Проект передан — завершено тестирование, система развернута на боевом сервере.

## Задание 3. Определение зависимостей

- Задачи Backend (2.1, 2.2, 2.3) зависят от Проектирования БД (1.2).
- Задачи Frontend (3.1, 3.2, 3.3) зависят от Макетов интерфейса (1.3).
- Фронтенд (3.3) и Бэкенд (2.2) могут разрабатываться параллельно, если заранее согласован контракт API.
- Тестирование (4.1) зависит от завершения разработки основного функционала (2.3 и 3.3).
- Внедрение (4.3) зависит от успешного прохождения тестирования (4.2).
