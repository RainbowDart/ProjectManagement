# Практическая работа №2. Разработка устава программного проекта

*(На основе проекта «Система управления задачами», взятого ранее).*

## 1. Устав проекта (Project Charter)

1. Название проекта: «TaskMaster» (Система управления задачами)
2. Обоснование проекта: В компании отсутствует единый инструмент для постановки и контроля задач, из-за чего часть поручений теряется, а сроки срываются.
3. Описание проблемы: Руководство не видит реальной картины загруженности сотрудников. Сотрудники используют разрозненные заметки и мессенджеры для обсуждения рабочих задач.
4. Цель по SMART: За 3 недели разработать веб-приложение, позволяющее создавать задачи, назначать исполнителей и отслеживать их статус (To Do, In Progress, Done), чтобы обеспечить прозрачность рабочих процессов в команде из 10 человек.
5. Заказчик: Отдел управления персоналом / Тимлид команды.
6. Целевая аудитория: Офисные сотрудники, менеджеры проектов.
7. Заинтересованные стороны:
   *   *Заказчик:* Хочет видеть прозрачные процессы и эффективность сотрудников.
   *   *Пользователи (сотрудники):* Хотят удобный и простой интерфейс, чтобы не забывать задачи.
   *   *Руководитель проекта:* Хочет сдать проект в срок и без конфликтов.
   *   *Разработчики:* Хотят реализовать интересный технический функционал.
8. Руководитель и участники: Руководитель — Иванов И.И. Команда: 1 Backend-разработчик, 1 Frontend-разработчик, 1 Тестировщик.
9. Границы проекта:
   *   *Входит:* Регистрация/авторизация, создание/редактирование задач, назначение исполнителей, смена статусов задач, базовый поиск по названию.
   *   *Не входит:* Чат внутри задач, интеграция с календарем (Google Calendar), загрузка файлов, отчеты по времени (тайм-трекинг), мобильное приложение.
10. Предполагаемые сроки: 3 недели (21 день).
11. Необходимые ресурсы: Сервер (VPS) для хостинга, репозиторий GitHub, бесплатный UI-kit для интерфейса.
12. Основные риски:
   *   Заказчик захочет добавить новые функции в процессе (риск расширения объёма).
   *   Болезнь ключевого разработчика.
   *   Неверная оценка сложности архитектуры.
13. Критерии успеха:
   *   Сотрудник может создать задачу и назначить её на другого.
   *   Статус задачи обновляется на сервере и сохраняется в БД.
   *   Система развернута и доступна по ссылке в интернете.
   *   Проект сдан в оговоренный срок (3 недели).
